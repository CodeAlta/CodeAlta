# WebApp UX/feature parity inventory from the TUI

Status: in progress (2026-09-22). Branch: `feature/dual-head-desktop`. This is an implementation checklist, not a claim that a disabled control, demo fixture, or static settings card constitutes parity. Check a row only after the real packaged Desktop flow, session switching, empty/error states, keyboard/accessibility behavior and functional tests are implemented. `src/CodeAlta.Tui/` is the behavioral reference; `src/CodeAlta/frontend/` and `src/CodeAlta/Desktop/Rpc/` are the WebApp. Existing `.alta` data formats must stay compatible, and desktop-only state stays under local desktop data. M7 remains deferred.

## Current architecture and evidence

- TUI prompt chrome: `Views/SessionWorkspaceView.cs:260-378` (`CreatePromptPanel`) composes a conditionally visible queued strip, image strip, status line, editor, then a **bottom** status bar with prompt/provider/model/reasoning selectors, provider summary, usage, reminders, session info, expand and send controls. Its controls bind to `ViewModels/SessionWorkspaceViewModel.cs` and `Views/{AgentPromptSelectorView,ModelProviderSelectorView,PromptComposerView,SessionStatusLineView}.cs`. `Views/SessionTabHostView.cs` owns a per-tab **vertical** timeline/composer splitter; `Views/CodeAltaShellView.cs` owns the horizontally resizable/collapsible navigator.
- TUI timeline and runtime projections: `App/{SessionHistoryCoordinator,SessionRuntimeTimelineRenderer,SessionRuntimeEventCoordinator}.cs`, `Presentation/Timeline/{SessionTimelinePresenter,ToolCallEventInterpreter,ChatTimelineVisualFactory}.cs`, `Presentation/Formatting/{ChatMarkdownFormatter,SessionUsageFormatter,ToolCallSummaryFormatter}.cs`.
- Desktop currently has a bounded persisted `WorkspaceHistoryRpc` and a **separate partial live display** (`Desktop/Rpc/SessionDisplayRpc.cs`); `frontend/src/main.tsx` stacks history, live display and asks in one scroller. `Desktop/Rpc/ConfigurationRpc.cs` exposes only a bounded read-only inventory of provider/plugin descriptors, **not** model enumeration, prompt listing or settings mutations. New mutable UI must first gain owned, validated runtime commands; disabled selects are not equivalent to the TUI.
- Desktop native mounted WebView2 verification is blocked in this environment (`WebView2 controller creation failed`). Preserve functional tests and explicitly record any remaining manual/accessibility qualification gap.
