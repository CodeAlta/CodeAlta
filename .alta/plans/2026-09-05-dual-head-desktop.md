## Objective

- Ship `CodeAlta` as a desktop-first .NET tool (`alta`) and `CodeAlta.Tui` as the terminal .NET tool (`altatui`). Retain the CodeAlta product identity in both.
- Provide all existing end-user TUI capabilities, with a native-feeling, keyboard-first desktop workspace: project/session navigator, concurrent session tabs, streaming timelines, editor tabs, notes, approvals, prompt composition, and discoverable settings.
- Enhance the coding/review experience in v1 with capable text/code/Markdown editors, source/preview/split Markdown modes, highlighted code, inline/side-by-side comparisons, built-in Mermaid diagrams, reorderable workspace tabs, and accessible resizable panes.
- Use NeoAstra **0.1.0 from NuGet**, React + TypeScript + Vite, packaged local assets, and generated .NET/TypeScript RPC. No HTTP application server, browser launch, SSR, or Node runtime in the installed application.
- Share orchestration, session/project discovery, configuration, credentials, drafts, prompt/skill/plugin management, permission policy, live-tool behavior, and persistence in .NET. Do not port business rules to TypeScript or duplicate them in desktop C#.
- Enforce one application owner of the shared data root, regardless of frontend. Multiple sessions may run independently within that owner; closing a tab is not stopping a run.
- Make plugin contracts frontend-neutral, with optional head-specific rendering. Preserve rich TUI support and establish a small project/workspace panel seam for later desktop canvases.
- Keep the reusable host suitable for a later headless agent. Do **not** implement remote hosting, network authentication, multi-user access, installers, automatic updates, arbitrary plugin JavaScript canvases, or a full IDE in this change.

## Design notes

### 1. Dependency direction and shared ownership

```text
CodeAlta.Tui (altatui)                 CodeAlta (alta)
  terminal controls/adapters            NeoAstra lifecycle + RPC adapter
  optional Plugins.Tui API              React/TypeScript presentation
              \                         /
                  CodeAlta.Hosting                  [new composition-only project]
                   /       |       \
          LiveTool    Orchestration    built-in providers/plugins
                           |
                   Agent / Catalog / Plugins
                                    |
                             Plugins.Abstractions    [toolkit-neutral]
```

- Put reusable runtime use cases, admission/execution tasks, interaction registry, authoritative run/queue state, and snapshot/event recovery in `CodeAlta.Orchestration`, with existing per-session ownership. These contracts contain no NeoAstra, XenoAtom controls, or actor references.
- Put config, draft/attachment storage, file access/encoding, prompt CRUD, and UI-state serialization in `CodeAlta.Catalog`, alongside current store ownership. Keep provider-specific auth/protocol behavior in `CodeAlta.Agent.*`.
- Add **one** `CodeAlta.Hosting` project for concrete application composition that must reference provider packages, built-in plugin implementations, and `CodeAlta.LiveTool`. Putting these references into orchestration would invert current dependencies or create a cycle through LiveTool. This project is not a second runtime or generic service framework.
- Compose one owned `CodeAltaHost`, model-catalog refresh service, shared provider-management workflow, plugin lifecycle, live-tool registry/dispatcher, ask/notes/reminders adapters, and startup/shutdown lifetime. Frontends supply narrow native/UI ports for dialog presentation, opening URLs/files, notifications, and diagnostics.
- Extract use cases incrementally by ownership, not wholesale moves of all `*Coordinator` classes. Keep `ShellStateStore`, `OpenSessionState` visual state, dispatcher-affine bindings, view models, focus/scroll logic, dialogs, `ShellCommand` activation, and timeline styling in TUI. Desktop uses lightweight render projections, not serialized TUI objects.
- Non-UI application commands take explicit project/session IDs and validated values, never read the currently selected DOM/TUI tab. Shared services re-evaluate policy/capabilities; availability shown in either UI is advisory.
- Keep the in-session **`alta` live-tool name unchanged in both heads**. It is an in-process gateway, not a shell invocation of whichever `alta.exe` is on PATH. Preserve child-session coordination, queue/steer, prompts, skills, plugins, MCP, notes, asks, reminders, results, and metrics.
- A later headless host supplies noninteractive ports and reuses the same use cases. No GUI assembly is loaded to list sessions, run providers, or manage plugins without UI; no remote transport is implemented now.

### 2. Startup, exclusive ownership, and shutdown

- Parse built-in early flags first. Help/version must not initialize native windows, providers, or source plugins. Use shared CLI parsing/formatting-independent metadata with separate executable names; keep terminal presentation only in TUI.
- Before logging/config recovery writes, source-plugin discovery/build/startup hooks, catalog initialization, or provider background tasks, acquire the existing shared-root ownership guard. Pure help/version can bypass it; any plugin command path with possible side effects cannot.
- Both executables use the same default `~/.alta/alta.lock`, independent of process name. Reuse the existing guard as the baseline, move it below the heads, and qualify cross-process races/stale locks on actual OSes. Unknown process-liveness/access failures must fail closed, never justify evicting a possibly live owner. Do not introduce NeoAstra's unrelated single-instance identity as the authoritative data lock.
- A second launch exits with a clear explanation of the existing owner and how to close it. No force takeover, killing the primary, or silently opening a second mutable host. Activation/launch forwarding is optional future polish, not needed for correctness.
- An explicit injected data root/test startup path is required for all automation. It propagates to locks, catalogs, auth, caches, plugins, drafts, and view state; production defaults remain unchanged. Tests never run against the currently active CodeAlta profile.
- Native startup enters `NeoApplication.Run` on the process main thread (STA on Windows). Create/register the main window before yielding, then initialize owned backend services asynchronously while showing a boot state. Marshal only native/UI operations via `NeoDispatcher`.
- Start provider probing and local session discovery independently. Corrupt config gets a recovery editor/diagnostic without replacing user files; locked cache errors remain explicit rather than falling back to a full journal scan.
- On main-window close/quit: show active-run/dirty-editor context; Cancel keeps everything running. Confirmed quit stops admission, flushes drafts/settings, cancels pending interactions appropriately, aborts/joins runs and probes/pumps, disposes owned host services once, and releases the lock last. Keep the native loop alive for async close callbacks. Surface cleanup failures/timeouts; cancellation is not proof of termination of noncooperative code.
- Closing a session tab only detaches its presentation and saves its draft. Renderer reload cancels observations, not active runs. A full application exit does not claim to continue work in the background or restore in-flight callbacks after process restart.

### 3. Durable state and handoff between heads

| State | Recommended ownership/behavior |
| --- | --- |
| Projects, sessions, lineage, canonical events | Existing catalog/journal APIs and paths, identical IDs in both heads. Preserve legacy tolerant readers. |
| Config, provider auth, MCP policy/connections, skills, prompts, plugins | Existing global/project roots and precedence. No browser storage as the source of truth; no desktop-specific credential copies. |
| Notes, queues, prompts/reminders/asks | Shared .NET use cases, using existing durable owners where available. Document existing persistence limits; do not invent restart persistence for transient services. Notes must not require a visible tab. |
| Saved prompt text and attachments | Catalog-owned draft/attachment stores, retaining current paths and formats. Save acknowledged revisions; flush on tab change, send, and quit. Test text/image ownership when queued/sent/cancelled. |
| Logical open tabs, selection, model/reasoning/agent prompt preferences | Extend the existing `ui-state.yaml` store additively. Preserve common session/draft/editor references across heads. Unknown/unavailable plugin tabs remain recoverable descriptors or visible unavailable entries, not silently deleted. |
| TUI layout vs desktop window geometry/density | Separate frontend-specific subsections within owned UI state (native browser cache under a dedicated cache subdirectory). Desktop must preserve TUI-only fields and vice versa. Retain legacy readers and known old fields. |
| Theme and language | Shared preference identity. Desktop-specific font size/zoom and window state are independent from terminal dimensions. |

- Store writes go through the existing owner with structured parsers and conflict-aware APIs. Use expected revision/content identity on settings, drafts, and editable files so stale document RPCs or external editor changes cannot clobber newer state, even with only one application process.
- Preserve TOML comments/unknown provider options and MCP JSON dialect on edit. Advanced config editing is an explicit sensitive operation, not raw config attached to the initial workspace snapshot. Mask existing secrets by default; secret replacement/clear is explicit, with no logging or browser persistence.
- Add migration fixtures for legacy UI state; keep any needed backup conflict-safe and non-overwriting. Do not bulk rewrite journals or clear SQLite caches as part of the rename. Pre-feature binaries need not understand new plugin APIs, but existing user state must remain readable by both new heads.

### 4. Desktop boundary: typed RPC, command lifetime, and events

- Reference `NeoAstra` centrally at 0.1.0. Use generated `NeoRpcService`/`NeoRpcMethod` bindings and source-generated JSON contexts. Keep bridge-specific declarations in `src/CodeAlta/Desktop/Rpc`; portable requests/snapshots live with shared .NET services.
- Expose small explicit services: workspace/catalog, sessions/history/actions, interactions/asks, settings/providers, prompts/skills, plugin management/actions, files/drafts, and native shell operations. Do not expose arbitrary service resolution, object graphs, shell commands, generic filesystem APIs, or unrestricted live-tool dispatch to JavaScript.
- DTOs contain stable IDs, versioned/discriminated content, safe summaries, revisions, capability/status values, and bounded pages. No `Visual`, delegates, provider runtime instances, or arbitrary `object` serialization. Use backend-generated enum/error codes and generated TS types; distinguish an accepted command from a completed run.
- Resolve project roots and global-session scope on the backend; the renderer cannot supply authoritative `SessionExecutionOptions`, approved roots, tools, credentials, or permission callbacks. Validate IDs, project association, method scope, allowed lengths/counts, and native grants on reads, writes, subscriptions, and responses.
- A send/queue/steer command has a client request ID and application-owned acceptance result. The shared application service owns/observes the execution task and cancellation. A document/request timeout must not cancel an accepted durable run. Explicit Stop maps to `AbortAsync`. Prevent duplicate sends after uncertain/retried responses with bounded session-owned admission records; do not add a process-wide run gate or a general deduplication system.
- Use one host-owned runtime reader. Produce normalized keyed projections and fan out bounded **nonblocking** subscriptions; tabs observe the host projection, never `SessionRuntimeService` directly. Adapt the existing TUI `RuntimeEventPump` to consume that projection (or remove its replaced read loop), so composing the shared host cannot accidentally create a second competing reader. Separate replaceable activity/text progress from authoritative completion/history/interaction state.
- Define a snapshot/observation handshake before coding: subscribe/register buffering under the projection owner, obtain a revisioned snapshot, then deliver updates after that revision; use stable event/item IDs for upsert/deduplication. A renderer epoch invalidates old callbacks. No wall-clock ordering assumptions.
- Detect upstream `DroppedRuntimeEventCount` changes and downstream overflow/sequence gaps. Mark affected observations stale (all relevant sessions if the upstream loss is unscoped), reconcile canonical history and active state, then replace the projection before resuming. NeoAstra channel credits acknowledge buffer admission, not DOM rendering, and cannot replay missing runtime events.
- Add an authoritative runtime/session snapshot query if the current APIs cannot recover busy/queue/status state without a TUI object. Add bounded stored-history pages/window reads at the existing journal/store boundary; merely slicing an already materialized multi-megabyte history in RPC is not sufficient. Keep provider-independent browsing and existing journal authority.
- Pending permission/user-input/`alta ask` requests live in a shared application-owned registry keyed by session/run/interaction IDs. It supports list/resolve/cancel with exactly-once completion, reconnect snapshots, and stale/replayed/wrong-session rejection. Keep this state outside lossy timeline notifications. Run cancellation/confirmed quit invalidates pending callbacks; temporary renderer reload retains them for reattachment.
- Cancellation of one observation releases subscriptions/channel resources only. Test enumerator/channel disposal and late completion; host disposal happens once after outstanding work is settled.

### 5. Trusted desktop integration and ordinary content handling

- Production entrypoint is a single manifest-backed `app://codealta/index.html` document with relative assets and hash verification. No Kestrel, localhost UI endpoints, external CDN assets, remote fonts, service workers, or externally hosted UI.
- Restrict navigation/new-window actions to the controlled application document. External HTTP(S) links open through a validated native opener. Reject `javascript:`, arbitrary `file:`, executable paths, and unexpected custom schemes. Native file/folder dialogs produce explicit backend grants; file IDs alone are not authorization.
- Use NeoAstra's standard packaged-app integration and supported policy configuration for the trusted frontend, including the libraries' normal runtime styles. No custom resource-provider/CSP framework or per-document nonce plumbing. Keep development origins and devtools overrides out of normal release startup.
- Treat model output, tool output, source files, Markdown, SVG, and plugin payload content as untrusted data. Disable raw HTML in Markdown, restrict links, and do not automatically fetch remote images (privacy/network leakage). Use controlled attachment IDs with size/MIME validation rather than exposing arbitrary local paths as asset URLs.
- Render Markdown, highlighted code and Mermaid directly in the main React document through their supported library APIs. Keep raw Markdown HTML disabled and Mermaid in strict mode with its built-in sanitization; do not add a second renderer or transport merely because Mermaid produces SVG. Arbitrary source HTML/JS execution is not a v1 feature.
- Source plugins remain trusted local .NET code, not sandboxed by this design. Frontend capability filtering does not make malicious in-process plugins safe. Project-source discovery/approval policy stays explicit and unchanged unless separately approved.
- Keep provider tokens and raw runtime/config graphs out of ordinary DTOs, logs, source maps, crash attachments, and browser storage. Explicit sensitive config editing is scoped and short-lived; user-entered credentials are sent only to backend-owned auth/config operations and then cleared from UI state.

### 6. Frontend stack and maintainability

- **React + TypeScript strict mode**, built by **Vite** (a build tool, not the UI framework), with npm and a committed lockfile. Use the NeoAstra package-staged `@neoastra/client` rather than an independently versioned registry client.
- CSS variables for semantic tokens, CSS Modules for component styles, and a small set of accessible unstyled Radix primitives for dialogs/menus/popovers/tabs where they reduce accessibility risk. No themed dashboard kit, CSS-in-JS framework, Next.js, router/server framework, or parallel state/query stack.
- One application-owned client projection store (for example React `useSyncExternalStore` with immutable snapshots), typed bridge adapter, and feature-local UI state. Components do not call raw RPC directly or derive provider/config policy. Subscription ownership is centralized, not one effect per rendered row.
- Use **CodeMirror 6** for all editable text, **react-markdown + remark-gfm + rehype-sanitize** for Markdown, **Shiki's JavaScript regex engine** for read-only code, and **Mermaid** for diagrams. The concrete package decisions, integration details, limits and alternatives are below; do not introduce a second editor engine or independent rendering pipelines per feature.
- Use **dnd-kit** for internal tab/list reordering, **react-resizable-panels** for split panes, and **TanStack Table/Virtual** for the actual large model/settings lists and transcripts. These libraries own interaction/presentation only; .NET still owns session actions, file/config saves, provider metadata and authoritative queries.
- Use Lucide for generic icons and a reviewed local subset of provider brand SVGs (for example from Simple Icons where available/licensed); missing brands get a legible generic icon plus label. No icon CDN or Nerd Font requirement for controls. Track licenses and trademark guidance.
- Keep a single `frontend/` within `src/CodeAlta`; suggested modules: `app`, `bridge`, `components`, `features/{workspace,sessions,composer,settings,editor,plugins}`, `styles`, and `tests`. This is not an npm monorepo or a generalized UI platform.
- Reuse/extend `CodeAlta.Catalog/SR.yml` as the translation source via deterministic frontend resource generation; no independent contradictory language preference or English-only regression. Frontend localizes view text, while structured backend diagnostics retain stable codes.

## Risks and challenges

1. **Hidden frontend business logic:** shared host existence does not prove complete reuse. The extraction inventory above and headless architecture tests are the main defense against a second implementation in desktop C# or TS.
2. **NuGet/native packaging:** a framework-dependent .NET tool must carry native RID libraries, assets, contract files, provider defaults, prompts, skills, and plugin build support. NeoAstra publish samples do not establish `dotnet tool install` behavior; resolve this before the UI migration.
3. **Cross-platform support:** WebView2 prerequisites, Linux GTK/WebKit versions, macOS main-thread/deployment target, fonts/IME, and actual ARM execution remain explicit gates. AOT annotations do not mean dynamically compiled source plugins are NativeAOT-compatible; keep framework-dependent .NET tool distribution as the baseline.
4. **Lost progress or approvals:** event streams are lossy, run requests may be long-lived, and UI callbacks currently own actionable state. Recovery/interaction tests precede rich UI work.
5. **Plugin breaking changes:** assembly references, source-build manifests, and reload lifetimes can fail only in installed packages. Test backend-only, dual-head, TUI-only, missing renderer, failing/reloading plugin cases from isolated packages; provide migration diagnostics.
6. **Content versus application code:** dependencies are trusted; rendered document text remains data. Keep ordinary Markdown/Mermaid defaults, validated links/attachments and existing backend permissions, with no secrets in ordinary view projections. Do not turn these defaults into a custom isolation subsystem.
7. **Large histories:** browser virtualization alone does not bound backend replay/allocation. Page through the actual owner and bound projection/subscription resources; retain search/copy/accessibility semantics.
8. **Dirty worktree/live host:** untracked `.alta/config.toml`, `.alta/mcp.json`, and `ultra_alta_2026-07-05_21_36_15_pid_53612.json.gz` are pre-existing user files. Do not read secrets, delete artifacts, stage them, or launch a second host against the user's data during this work.
9. **Long-running branch drift:** keep self-contained commits with verification; merge-base updates must preserve work and not mix unrelated fixes. Do not publish a half-parity desktop as the replacement `alta` merely because the package builds.
