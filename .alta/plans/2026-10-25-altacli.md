# altacli: headless CodeAlta CLI with an ACP server mode (#216)

Issue: https://github.com/CodeAlta/CodeAlta/issues/216 (read it whole: decisions, storage modes, JSONL, ACP table).
Integration branch: `feature/altacli`. Steps run in child worktrees (`alta/...` branches based on `feature/altacli`)
and are merged back by the driving session.

## Design summary

- `src/CodeAlta.Cli` (`altacli`, package `CodeAlta.Cli`, dotnet tool like `altatui`). XenoAtom.CommandLine +
  XenoAtom.Logging, no `XenoAtom.Terminal.*`. Commands: `run`, `acp`, `alta`, `models`, `auth check`.
- One loop, several faces: a shared `HeadlessSessionDriver` in `CodeAlta.Orchestration` (create/resume, send, wait
  until settled, abort, result) used by `run` and `acp`; each face projects `SessionRuntimeEvent`s.
- Full trust: bypass permission mode + allow-all handlers; no user input, no `alta ask`/`review`/`reminder`/UI
  commands (allow-list registry); headless instructions in the system prompt; review-before-commit off.
- Plugins: `PluginFrontends.Cli` opt-in (`All` stays Terminal|Desktop); git, jira, mcp, acp declare it.
- Storage: never the shared `alta.sqlite3`, never `alta.lock`; a private throwaway database per process (the host
  cannot run without one), listing/resume read journals. Only `auth/` and `cache/` written under the global root.
  - Visible (default): journals in `~/.alta/sessions/`, a marker per new session in `sessions/markers/`,
    Desktop/TUI watch markers and project the sessions, follow leased-elsewhere sessions live and read-only.
  - Isolated (`--isolated`): state root `~/.alta/cli/` (or `--profile <dir>` for a whole separate profile).
  - Per-session lease (`sessions/leases/<id>.lease`, OS-held handle) taken by every frontend that runs a session.
  - Sessions in a folder outside the catalog: no project registered, bound to the folder; listed by Desktop/TUI
    once the folder is a project (sessions are matched to projects by folder).
- JSONL schema v1 (`--format jsonl`): `session` header first, deltas, messages, tools, children, jobs,
  compaction/retry/fallback, usage, errors, a last `result` record. Text mode: final answer only on stdout.
- Exit codes: 0 completed, 1 failed, 2 invalid usage/config, 3 aborted (signal), 4 timeout, 5 session in use,
  6 provider not ready (sign-in, missing model), 7 invalid structured output.

## Steps

### A. Foundations (parallel, independent areas)
- [ ] A1 Plugins + `alta` registry: `PluginFrontends.Cli`; built-ins git/jira/mcp/acp declare it; registry
      options with an allow-list of built-in roots applied to the command tree, help, policies, root guidance;
      tests; `doc/plugins.md`, `doc/live-tool.md`, plugin author docs.
- [ ] A2 ACP server library in `CodeAlta.Acp`: `AcpAgentServer`, `IAcpAgent`/`AcpAgentBase`, client endpoint
      (`session/update`), `$/cancel_request`, error codes public (`auth_required`), error data, update/content/
      config-option builders; tests driving it with `AcpClient` over pipes.
- [ ] A3 Catalog primitives: config overlay (`--ignore-user-config`, `-c key=value`, inline config variable,
      `--strict-config`, read-only store), cross-process `SessionLease`, `SessionMarker` store; tests.

### B. Runtime (sequential)
- [ ] B1 Headless host and sessions: host options for read-only global state (no AGENTS.md, no view-state
      seeding, no project persistence, no database maintenance, private database); sessions in uncataloged
      folders (create, resume); caller-chosen session id; tier resolution shared; tool disabling by pattern;
      `CODEALTA_SESSION_ID`/`AI_AGENT` markers for child processes; headless instructions; `WhenSettledAsync`
      (root + descendants + queue + jobs + fallback); `HeadlessSessionDriver`; tests with a fake provider.
- [ ] B2 Visible mode across frontends: lease integration in `SessionRuntimeService` (acquire with an entry,
      refuse foreign-leased mutations with `session_in_use`), marker watcher + projection, live follow of
      leased-elsewhere sessions, Desktop (list refresh, running-elsewhere read-only state) and TUI refresh; tests.

### C. The executable
- [ ] C1 `CodeAlta.Cli`: composition, stdout guard, logging, `run` (input, text/JSONL output,
      `--output-last-message`, `--output-schema`, `--timeout`, signals, exit codes), `alta`, `models`,
      `auth check`, storage modes and options; tests in `CodeAlta.Cli.Tests`.
- [ ] C2 `altacli acp`: ACP agent on the driver (table of #216), tests with `AcpClient`.

### D. Finish
- [ ] D1 Packaging (`CodeAlta.slnx`, csproj, readme), user guide page (`site/docs`), `doc/` architecture updates.
- [ ] D2 Full validation: `dotnet build/test -c Release`, `npm test`, `lunet build`; dev-instance check of a
      visible `altacli` session in Desktop.
- [ ] D3 Adversarial review by a codex GPT 6.1 Sol xhigh session; iterate on valid findings.
- [ ] D4 Update #216 (and its corrections, e.g. provider keys come from `api_key_env` of the config).
